# exam-gadh-terraform

Infrastructure for ExamGadh on AWS (Mumbai, `ap-south-1`), as approved in
`exam-gadh-docs/docs/architecture/ARCHITECTURE.pdf` (v0.1, amendment A1: Terraform has its own repo).

```
bootstrap/        run once by a human: state bucket, lock table, GitHub OIDC provider, CI roles
modules/          network, app_server, database, storage (S3+CloudFront), ecr, ops (alarms, budget, schedule), deploy_roles
envs/dev/         the dev environment (exists now)
envs/prod/        created later by copying envs/dev and applying prod values (see below)
.github/workflows/terraform.yml   fmt, validate, tfsec, plan on PR; apply only by manual dispatch + reviewer approval
```

## What it creates (dev)
VPC (1 public subnet, 2 private subnets, no NAT) · EC2 `t4g.small` (Docker host, no SSH, SSM only, IMDSv2) ·
RDS PostgreSQL 16 `db.t4g.micro` (private, encrypted, password in Secrets Manager) · S3 media bucket + CloudFront ·
3 ECR repos (`api`, `web`, `admin`) · GitHub OIDC deploy role · CloudWatch alarms, SNS email, monthly budget ·
EventBridge schedule that stops EC2/RDS at 23:00 IST and starts them at 07:45 IST (Mon–Sat).

Estimated cost: about USD 38/month for dev (see the architecture doc for assumptions; re-check in the AWS calculator).

## First-time setup (a human does this; nothing here is applied automatically)
1. Install Terraform >= 1.9 and configure AWS admin credentials for the account.
2. `cd bootstrap && terraform init && terraform apply` — creates state bucket, lock table, OIDC provider and the
   `examgadh-terraform-plan` / `examgadh-terraform-apply` roles. Note the outputs.
3. `cd ../envs/dev`; copy `backend.hcl.example` to `backend.hcl` (fill the bucket name) and
   `terraform.tfvars.example` to `terraform.tfvars` (set `alert_email`).
4. `terraform init -backend-config=backend.hcl && terraform plan` — review, then `terraform apply`.
5. Confirm the SNS subscription email. Create the secrets in SSM Parameter Store (see below).
6. In GitHub (this repo) set Actions variables `AWS_PLAN_ROLE_ARN`, `AWS_APPLY_ROLE_ARN`, `TF_STATE_BUCKET`,
   `TF_LOCK_TABLE`, `ALERT_EMAIL`, and create the Environment `dev-apply` with a required reviewer.
7. In the backend/frontend repos set `AWS_DEPLOY_ROLE_ARN` (output `github_deploy_role_arn`) and `AWS_REGION`.

## Secrets (never in code or state)
Create as SecureString under `/examgadh/dev/`: `jwt_private_key`, `razorpay_key_id`, `razorpay_key_secret`,
`razorpay_webhook_secret`, `google_client_id`, `fcm_service_account_json`. The database password is generated by RDS
into Secrets Manager (output `database_master_secret_arn`).

## Adding prod later
Copy `envs/dev` to `envs/prod`; set `environment = "prod"`, `instance_type = "t4g.medium"`,
`db_instance_class = "db.t4g.small"`, `enable_schedule = false`, `monthly_budget_usd = 110`, longer backups,
`deletion_protection = true`, `skip_final_snapshot = false`, `force_destroy = false`, `multi_az` if the SLA rises, and a
`prod/terraform.tfstate` state key. Add an `AWS_PLAN`/apply path with its own protected GitHub Environment.

## Safety rules
`terraform apply` is never run from a laptop session by automation here; CI applies only a reviewed plan after approval.
Run `terraform fmt -recursive` and `terraform validate` before every commit.
